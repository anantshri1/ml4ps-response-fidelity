statistically even; FNO's edge is avoiding Born's catastrophic failures.

so a complex alpha would hide genuine phase error as false alignment. Validated
by a synthetic i*A gate: complex-alpha scores a pure 90-deg phase error as
cos~1 (aligned); real-alpha correctly scores it cos~0 (orthogonal).

apples-to-apples slope across N. The N=2000/M16 config table (first table
above) is 4-seed. N=2000/lam=0.1 therefore reads differently in each table
(3-seed: 0.9946/0.9941; 4-seed: 0.9943/0.9940) — both correct, tag which
is which.

14. LINEARIZED VALIDITY RADIUS, f64, seed0, 20 samples x 4 dirs   [CANONICAL]
================================================================
Metric: err_J(eps) = ||dpsi_true - eps*(J.dV)|| / ||dpsi_true||
  dpsi_true = solver(V+eps*dV) - solver(V); dV unit-norm Gaussian;
  J.dV via jax.jvp. All J evaluated against the same solver truth. ||V||~19.2.

eps* (largest eps with mean err < tol):
  operator        0.05     0.10     0.15     0.20
  J_true          >1       >1       >1       >1       <- true dynamics near-linear to eps>1
  J_fno lam0      <1e-4    <1e-4    <1e-4    <1e-4    <- no valid regime at any eps
  J_fno lam0.1    <1e-4    <1e-4    >1       >1       <- valid only if tol > ~0.11 plateau

Why FNO curves are flat: in the true-linear regime dpsi_true ~ eps*(J_true.dV),
so eps cancels in the ratio -> err_J -> ||(J_true-J).dV||/||J_true.dV||,
which is eps-independent.
  J_true : that term = 0 -> residual is O(eps) nonlinearity -> slope-1 diagonal.
  J_fno  : nonzero constant (~0.63 lam0, ~0.11 lam0.1) -> flat plateau.

FNO response error is scale-invariant in eps — representational, not a
linearization artifact (which would vanish as eps->0). No perturbation is
small enough to make J_fno lam0 valid. J_true eps*>1 rules out "linearization
is hard here" as an explanation.

Cross-check: lam0 plateau ~0.63 ~ Frobenius floor 0.573 (directional average,
O(1) weighting). Consistent.

16. TIMING / AMORTIZATION, f64, nx=128, nt=1000, seed0, CPU (median of 50)
================================================================
Per single-sample query (one (psi0, V)):
  solver forward (psi_T)     2.25 ms
  FNO forward    (psi_T)     0.26 ms      -> forward surrogate  8.6x
  J_true (128 JVPs / scan) 121.5 ms
  J_fno  (128 JVPs / net)   15.7 ms      -> response surrogate 7.7x (saving 105.7 ms/query)

Both Jacobians cost ~55-60x their own forward (jacfwd over 128-dim V);
response surrogate speedup tracks the forward speedup.

Break-even n* = T_train / saving  (saving = 0.106 s/query):
  DINO lambda=0.1 (response-trustworthy): T_train ~780-960 s -> n* ~7.4k-9.1k queries
  forward-only lambda=0: T_train ~180-300 s -> n* ~1.7k-2.8k, but this model
    is response-wrong (§2) — its cheaper training is not citable for a response claim.

No speed win at this scale: one training run already costs more than exact
J_true for the entire 200-sample testbed (200 x 121.5 ms = 24.3 s), and n*
is thousands of queries vs 200 available. The testbed is a controlled
instrument, not a production speed claim. The per-query win transfers to
regimes where one J_true costs seconds-to-minutes (3D, fine grids, stiff
dynamics) AND query count >> n* (optimization, UQ, inverse design) —
contingent on response accuracy being established first.

Note: DINO training consumes J_true-JVP evaluations as supervision targets,
so the exact operator is a training-time prerequisite. Forward-only avoids
this cost but is response-wrong — derivative supervision and response fidelity
cannot both be obtained for free.

CPU timing only; ratios are portable, absolute ms are machine-specific.
